# EPIC-T-07: AI チャット抽出 (vitanota AI 連携第一弾) 🔴 Must

## エピック概要

教員が思いついたことをチャット形式で書き散らすと、AI が「タスク」または「日誌ネタ」として分類し、その場で承認 / 編集 / 棄却できる機能。フォームを開く摩擦をなくし、入力頻度を桁違いに上げることで vitanota の生死線 (日誌記録量 + タスク入力量) を支える。

**位置付け**:
- 既存 EPIC-T-05 「タスク管理」(Won't フェーズ 2) とは独立。タスク管理機能自体は既に本番稼働中 (TaskBulkCreateForm)、本エピックはその入力経路の **追加** であり、既存タスク機能の置き換えではない
- 既存 EPIC-T-06 「AI 週次レポート」(Won't、2026-04-27 Anthropic 接続全面凍結) とは別物、AI 連携の戦略を仕切り直して再開

## ストーリー一覧

### US-T-070: チャットでサッと書き散らす (起動 UX) 🔴 Must

**ストーリー**: 私は教員として、思いついた瞬間にすぐ書き散らせる場所が欲しい。なぜなら、フォームを開くたびに「今は時間ない」と書くのをやめてしまっていて、結果タスクも日誌も入力されないままになっているから。

**受け入れ基準**:
- Given: 教員 (teacher / school_admin) としてダッシュボードにログインしている
- Given: スマホで授業の合間、3 秒しか時間がない瞬間
- When: 画面右下のフローティングバブルをタップする
- Then: 画面下からモーダル/シートが立ち上がり、200ms 以内にテキスト入力欄にフォーカスする
- Then: メッセージ送信は最大 2000 文字、ペーストでも書き殴りでも受け付ける
- Then: × / 背景タップ / ESC / ブラウザ戻る、いずれでもセッション終了

- Given: PC で職員室にいる
- When: フローティングバブルをクリックする
- Then: 画面中央〜右側にモーダルが開き、同じ UX で利用できる

**INVEST**: Independent ✓ / Negotiable ✓ / Valuable ✓ (起動 UX 自体が摩擦解消の価値) / Estimable ✓ / Small ✓ / Testable ✓

**関連 AC / NFR**: AC-CE-01, 02, 03, 04, 05, 06、NFR-CE-02

### US-T-071: AI に書いた言葉をタスクとして拾ってもらう 🔴 Must

**ストーリー**: 私は教員として、「保護者連絡しなきゃ」と書いただけで、AI が勝手にタスク候補を提案してくれて欲しい。なぜなら、自分でフォームを開いて title・description・due_date を埋める手間が省けるから。

**受け入れ基準**:
- Given: チャットモーダルが開いている
- When: 「明日の昼休みまでに田中さんの保護者に連絡」と送信する
- Then: 3 秒以内 (p95) に AI 抽出結果が返り、送信メッセージ直下にタスク候補がインラインバブルで表示される
- Then: タスク候補には title (例: 「田中さんの保護者に連絡」)、due_date (例: 翌日)、source_chat_snippet (元メッセージ抜粋) が自動入力されている
- Then: ワンタップで承認すると tasks テーブルに INSERT、assignees は自分のみ自動セット

- Given: 1 メッセージに複数の用件が混じっている
- When: 「保護者連絡しなきゃ、運動会の準備もある」と送信する
- Then: タスク候補が 2 件、それぞれインラインバブルで並んで表示される

- Given: AI 生成内容を直したい
- When: タップで編集モーダルを開く
- Then: title / description / due_date を自由に書き換えて承認できる

- Given: AI 抽出が外れた
- When: スワイプ or × で棄却する
- Then: 候補が消え、tasks テーブルには何も入らない

**INVEST**: Independent ✓ / Negotiable ✓ / Valuable ✓ (タスク入力フリクション解消が直接価値) / Estimable ✓ / Small ✓ / Testable ✓

**関連 AC / NFR**: AC-CE-07, 08, 09, 10, 12, 13, 14, 18、NFR-CE-01

### US-T-072: AI に書いた言葉を日誌 (diary) として拾ってもらう 🔴 Must

**ストーリー**: 私は教員として、「○○さん今日元気なかった」と書いただけで、AI が勝手に日誌の下書きを作って欲しい。なぜなら、日誌を書くために `/journal` を開くこと自体が摩擦になっていて、書かないまま忘れてしまうから。さらに「絶対に何か拾って欲しい」 — 書いたのに無視されると、書く動機が消えるから。

**受け入れ基準**:
- Given: チャットモーダルが開いている、教室の隙間で 1 分しかない
- When: 「6 年 1 組、運動会の練習で田中さんが他の子に声かけてた、すごく成長」と送信する
- Then: 3 秒以内に AI 抽出結果が返り、**diary 候補** のインラインバブルが表示される
- Then: 日誌候補には `kind='diary'`、content (最大 200 字)、source_chat_snippet が含まれる
- Then: **mood は空** (AI は触らない、AC-CE-11 厳守、memory: mood AI 不可侵原則)

- Given: 1 メッセージがタスク + diary 両方に該当する
- When: 「○○さん今日元気なかった、明日声かけよう」と送信する
- Then: タスク候補 (「明日 ○○ さんに声かけ」) と diary 候補 (「○○さん今日元気なかった」) の 2 つがインラインバブルで並ぶ

- Given: AI が「タスクっぽくない」と判定 (例: 軽い感想・短い断片・知見記録)
- When: 「コーヒー切れた」「今日も雨かぁ」「6 年 1 組の運動会練習で田中さんが声かけてた」のような書き散らし
- Then: **絶対に何か返す**: `diary` 候補として最低 1 件提案 (AC-CE-08 / AC-CE-09a)
- Then: 教員は「無視された」と感じない、書き続ける動機が保持される

- Given: ワンタップで承認する
- When: kind='diary' なら US-T-074 で 温度感コメント + mood 絵文字選択、kind='task' なら mood UI なし即 INSERT
- Then: 該当テーブル (tasks or journal_entries) に INSERT (source_chat_snippet + 必要なら mood)、本人だけが閲覧可 (既存 RLS)

- Given: 知見として深く残したい / つぶやきとして軽く残したい
- When: 教員は手動で既存 `/journal/new` を開いて EntryForm から投稿する
- Then: 既存 UX で knowledge / tweet を選択可、AI 抽出経由とは棲み分け

**INVEST**: Independent ✓ (US-T-074 と分離可能、mood なしでも保存可) / Negotiable ✓ / Valuable ✓ (生死線 A 救出の直接価値、書き続ける動機保持) / Estimable ✓ / Small ✓ / Testable ✓

**関連 AC / NFR**: AC-CE-07, 08, 09, 09a, 11, 11a, 11b, 11c, 12, 13, 14, 19、NFR-CE-01

### US-T-073: チャットを閉じても安心 (未承認候補の防護) 🟡 Should

**ストーリー**: 私は教員として、チャットモーダルを閉じる前に「まだ承認してない候補があるよ」と教えて欲しい。なぜなら、せっかく AI が抽出してくれた候補をうっかり消してしまうとガッカリするから。

**受け入れ基準**:
- Given: チャットセッション中、未承認候補が 2 件溜まっている
- When: モーダル/シートを閉じようとする (× / 背景タップ / ESC / ブラウザ戻る)
- Then: 確認ダイアログ「未確認候補が 2 件あります。閉じますか?」が表示される
- Then: 「閉じる」を選ぶと候補は揮発、「戻る」を選ぶとセッション継続

- Given: モーダル/シート上部に「未確認 (N)」アイコンがある
- When: アイコンをタップする
- Then: 未承認候補だけをまとめた別パネルが開き、まとめて承認/編集/棄却できる

- Given: ブラウザリロード / 別タブ遷移 / セッションタイムアウト
- When: 偶発的に画面が消えた
- Then: チャットメッセージも候補も完全に消える (DB 永続化なし、AC-CE-20 / NFR-CE-09)
- Then: ただし既に承認済みのタスク/日誌は失われない (tasks / journal_entries 保存済み)

**INVEST**: Independent ✓ / Negotiable ✓ / Valuable ✓ (心理的安全性、信頼性) / Estimable ✓ / Small ✓ / Testable ✓

**関連 AC / NFR**: AC-CE-16, 17, 20、NFR-CE-09

### US-T-074: diary 候補に気分絵文字を選ぶ (mood UI、教員選択死守、温度感コメント付き) 🔴 Must

**ストーリー**: 私は教員として、**diary 候補** を承認するタイミングで「今の気分」を絵文字で選びたい。なぜなら、自分の体調・状態を後で振り返るときに mood が手がかりになるから。ただし、機械に自動で気分を判定されると気持ち悪いから、自分で選びたい。また、AI から「お疲れさま」みたいな温度感のある一言があると、書き続ける気持ちになれる。

**受け入れ基準**:
- Given: **diary 候補** (kind='diary') のインラインバブルが表示されている
- When: 承認ボタンをタップする
- Then: ポップアップ表示 — **温度感固定コメント** (例: 「お疲れさま、書いてくれてありがとう。今の気分も教えて」) + 気分絵文字選択 UI (5 段階ピッカー、例: 😀 🙂 😐 😟 😢) が表示される
- Then: 温度感コメントは **静的固定文言** (AI 生成ではない、メッセージ内容に応じた動的反応は出さない、踏み絵セーフ確保)
- Then: mood 選択は **必須** (chimo 確定 2026-05-11、既存 diary 仕様踏襲)

- Given: 気分絵文字を選んだ
- When: 「この気分で保存」ボタンを押す
- Then: journal_entries に mood + content + source_chat_snippet + kind='diary' で INSERT

- Given: task 候補の承認 (kind='task')
- When: 承認ボタンをタップする
- Then: **MoodPicker / 温度感コメント は表示されない**、タスクは即 INSERT (tasks テーブル)

- Given: AI は mood 絵文字を提案しない、推定しない (踏み絵厳守、memory: feedback_mood_ai_untouchable.md)
- Then: AI が「あなたは今 😢 ですね」のような表示は一切出ない (AC-CE-11)
- Then: 温度感コメントも AI 生成ではなく **静的固定文言** (メッセージ内容で文言が変わらない、観測感ゼロ)

- Given: 連続 diary 候補が複数ある
- When: 1 件目承認 → MoodPicker → mood 選択 → 保存 → 2 件目承認
- Then: 2 件目の MoodPicker は **直前の mood が default 予選択** されている (ワンタップ承認可、別 mood に変えるには選び直し)
- Then: 連続承認時の摩擦を最小化、ただし mood が変わる可能性も尊重

**INVEST**: Independent ✓ (US-T-072 と分離可能) / Negotiable ✓ / Valuable ✓ (mood の手がかり化、後の振り返り資産) / Estimable ✓ / Small ✓ / Testable ✓

**関連 AC**: AC-CE-11, 15

### US-T-075: Bedrock 障害時もタスク管理は使える (信頼性) 🟢 Could

**ストーリー**: 私は教員として、AI チャット抽出が壊れた日でも、既存のタスク登録 / 日誌作成は普通に動いて欲しい。なぜなら、新機能の障害で本業が止まると教員業務に支障が出るから。

**受け入れ基準**:
- Given: AWS Bedrock がタイムアウト / 5xx を返す
- When: 教員がメッセージを送信する
- Then: 自動 1 回 retry、それでも失敗ならエラーバブル「抽出できませんでした、再試行できます」表示
- Then: 「再試行」ボタンで教員が手動 retry 可

- Given: チャット抽出機能全体が利用不可
- When: 教員が既存の TaskBulkCreateForm を開く / 日誌画面 (/journal/new) を開く
- Then: 通常通り稼働、タスク作成・日誌作成が完了する (既存 UX は AI 連携と独立、リスク対称性確保)

**INVEST**: Independent ✓ / Negotiable ✓ / Valuable ✓ (リスク管理、教員業務継続性) / Estimable ✓ / Small ✓ / Testable ✓

**関連 NFR**: NFR-CE-11, 12, 13
